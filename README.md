# 🚗 挪车助手小程序

扫码 → 微信通知车主 / 一键拨号。基于**微信云开发 + 原生小程序**，个人主体可跑，自用场景零成本。

> **二次开发请先改这 3 处**（仓库里留的是占位/示例值）：
> 1. `project.config.json` → `appid`：换成你自己的小程序 AppID
> 2. `miniprogram/config.js` → `CLOUD_ENV`：换成你的云开发环境 ID
> 3. 云函数 `car` →「配置 → 环境变量」填 `MP_APPID` / `MP_APPSECRET`（详见第 4 步）
>
> AppSecret 一律走云函数环境变量，**不写在代码里**，仓库无任何密钥泄露风险。

## 它长什么样

**车主这一侧（3 步）**

| 步骤 | 页面 | 动作 |
|---|---|---|
| 1 | 首页引导 | 点「添加车辆」 |
| 2 | 添加车辆 | 填**车牌号**（油车蓝牌 / 新能源绿牌自动识别）、选填手机号与车辆备注 → 生成挪车码 |
| 3 | 挪车码页 | 保存到相册 → 打印 → 贴前挡风玻璃内侧 |

**扫码方这一侧（一个页面，两条路）**

```
扫挪车码
   │
   ├─ 🔔 微信通知车主  ← 主路径，不暴露号码
   │     可勾选快捷留言（挡住我了 / 挡了消防通道 / 没关灯…）
   │
   └─ 📞 直接拨打      ← 号码默认脱敏显示（138****8888），点击后由微信系统展示完整号码并拨出
```

> 两条路都走不通的情况（车主暂停通知、通知额度用完）会自动引导到拨号，不会让扫码方卡住。

**空白挪车码（先印贴纸，后绑车辆）**

首页点「＋ 空白挪车码」→ 立刻出一张**不含任何车辆信息**的码 → 打印贴到车上 →
任何人扫码填写车牌即完成绑定。不必提前知道车牌号，适合先印好一批贴纸。

| 场景 | 流程 |
|---|---|
| 自己印、自己用 | 生成码 → 打印贴车 → 自己扫码绑定 |
| 转送他人 | 生成码 → 把贴纸给别人 → 对方扫码绑定（绑定后从你的列表消失） |

> ⚠️ 绑定规则是**先到先得**：谁先扫码绑定这张码就归谁，绑定后所有权（openid）转移给绑定者。
> 所以空白码在绑定之前要保管好，别让无关的人先扫到。详见 [第 11 步](#第-11-步空白挪车码先印后绑可选)。

## 一、先看清四条硬约束

| 约束 | 说明 | 本项目的处理 |
|---|---|---|
| **体验版路人是扫不开的** ⚠️ | 体验版小程序码只有体验成员能打开，非成员扫码提示「无权限访问」 | **挪车码必须走正式发布版**才能被路人扫开，详见第四节 |
| **小程序上线必须先 ICP 备案** | 2023 年起工信部强制要求，未备案无法提交审核发布。个人主体可备案，全程免费，7–20 个工作日 | **注册完立刻提交备案**，它是整个流程里最慢的一步，与开发并行 |
| **个人主体拿不到手机号** | `getPhoneNumber` 仅对企业/个体工商户开放，个人小程序调用不会返回真实号码 | 车主**手输**手机号，不做一键授权 |
| **订阅消息是「一次性」的** | 车主授权 1 次 = 只能推送 1 次，不是长期订阅 | 做**额度累积**：每次进小程序自动补授权并累加，页面上显示「可通知 N 次」 |

> 关于费用：备案免费、个人主体免认证费（300 元/年那项个人本来也办不了）。
> 云开发免费环境在**小程序发布后第 15 天到期**，之后需转付费，最低 **19.9 元/月**（基础套餐原价 39，5 折长期有效）。详见下方「上线后的持续费用」。
>
> ⚠️ **不开自动续费的风险**：套餐到期次日起 7 天内可续费找回，**超过 7 天（第 8 天起）系统释放资源，数据清除且不可恢复**——所有挪车码失效、已绑定的车辆全部丢失。务必开自动续费并预充值。
>
> 关于虚拟号隐私通话（AXB，双方都看不到真实号码）：需要企业/个体工商户主体 + 微信认证，个人主体做不到，本项目也不涉及。

### 关于「体验版自用」这个说法的更正

早期版本本文档建议「体验版自用，0 元跑通」，**这个建议对挪车场景是错的**：体验版只能让已添加的体验成员打开，而挪车码恰恰是贴在车上给**陌生路人**扫的。你本人扫码一切正常，别人扫就是「无权限访问」。

体验版的正确用途只有一个：**开发调试阶段**。想真正用起来，必须完成备案并发布正式版。

## 三、从 0 到 1 操作步骤

### 第 1 步：注册小程序（约 10 分钟，免费）

1. 打开 https://mp.weixin.qq.com →「立即注册」→「小程序」
2. 填邮箱（**未注册过微信公众平台的邮箱**）→ 邮箱激活
3. 主体类型选 **个人** → 填身份证 + 管理员微信扫码验证
4. 注册完成后，进入后台 →「开发」→「开发管理」→「开发设置」，复制 **AppID**

> 个人主体不需要 300 元认证费。缺点是类目受限，但我们走体验版不提审，不受影响。

### 第 2 步：开通云开发

1. 下载安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版 Stable Build）
2. 打开工具 → 导入项目 → 目录选 `move-car` → 填入你的 AppID → 导入
3. 点击工具栏「**云开发**」按钮 → 开通 → 创建环境
   - 环境名称随意，如 `move-car`
   - 计费方式选 **按量付费 / 免费体验环境**（小程序未发布前不收费）
4. 创建完成后，在云开发控制台「设置」→「环境 ID」，复制下来

**创建两个数据库集合**（名字必须一字不差，云函数里写死了）：

| 集合名 | 用途 | 建议权限 |
|---|---|---|
| `car_codes` | 车辆与挪车码 | 仅管理端可读写 |
| `notify_logs` | 通知记录 + 被扫码记录（用于频控） | 仅管理端可读写 |

> 权限选「仅管理端可读写」最安全：所有读写都走云函数（云函数默认 admin 权限），扫码方无法直接拖库。
>
> **集合可以偷懒不建** —— 第 4 步跑 `health` 自检时会自动创建，但建完你要手动把权限改成「仅管理端可读写」（自动创建的默认是「仅创建者可读写」）。
>
> `notify_logs` 里 `type` 有三种：`view`（被扫码）、`notify`（发送通知）、`call`（预留，拨号由微信客户端直呼不经过服务端）。车主端只展示后两种。

### 第 3 步：部署云函数

> 控制台里「新建云环境 / 选订阅模板」这两步必须你本人扫码登录才能做，脚本替不了。
> **真正能脚本化的只有「上传云函数」这一步**，已封装好：

**唯一方式（开发者工具手动上传，最可靠）**：

1. 开发者工具里，左侧右键 `cloudfunctions/car` 目录 →「**上传并部署：云端安装依赖**」
2. 看到「部署成功」即可；定时触发器随 `config.json` 一并创建

（仓库早前的一键 CLI 脚本 `scripts/deploy.sh` 依赖开发者工具「服务端口 + 本机 CLI 环境」，已随脚本移除；手动右键上传等价且更稳定。）

1. 编辑 `miniprogram/config.js`，把第 2 步复制的**环境 ID** 填进 `CLOUD_ENV`
2. 在开发者工具里，右键 `cloudfunctions/car` 目录 →「**上传并部署：云端安装依赖**」
3. 看到「部署成功」提示即可

> **⚠️ 这一步是「微信通知」能否工作的关键（绕开坏链路）**
> 本项目不再依赖 `cloud.openapi`（你的环境该链路已损坏，会持续报 `INVALID_WX_ACCESS_TOKEN`），
> 改为用 **AppID + AppSecret 直连微信标准 HTTP 接口**。因此必须给云函数 `car` 配置两个环境变量：
>
> 1. 云开发控制台 →「云函数」→ `car` →「配置」→「环境变量」
> 2. 新增两条：
>    - `MP_APPID` = `wxYOUR_APPID_0000`（换成你自己的）
>    - `MP_APPSECRET` = 你的小程序 **AppSecret**
>      （获取位置：公众平台 → 开发 → 开发管理 → 开发设置 → AppSecret，需管理员扫码）
> 3. 保存后**重新部署一次云函数**，让环境变量生效
>
> 不配这俩，健康自检的「订阅消息模板」会明确报错「未配置 MP_APPID / MP_APPSECRET」，
> 微信通知和小程序码都出不来；但**扫码显示手机号拨号不受影响**（它不依赖云端 openapi）。

### 第 4 步：跑一次部署自检（强烈建议）

不用打开小程序，在云开发控制台就能一次验完最容易卡的四件事。

云开发控制台 →「云函数」→ 点 `car` →「云端测试」→ 测试参数**直接留空或填两个花括号**：

```json
{}
```

> 不填 `action` 时云函数默认跑 `health`，所以不用担心 JSON 写错。
> 如果你填了完整写法却弹出 **「内容不是合法的json」**，那不是代码问题——
> 是输入框在发送前解析失败，两个原因二选一：
>
> 1. **引号被转成了中文引号** `“ ”`。这是最常见的原因，尤其是在聊天窗口/网页里复制过来的。
>    解决：别复制，在输入框里**手打**一遍，确保是半角 `" `。
> 2. 带了不可见字符（不换行空格、零宽空格）。同样靠手打解决。
>
> 实在不想打 JSON，输入框里只写一个单词 `health` 也能跑（代码已做容错）。

点运行，返回里看 `checks` 数组：

| 检查项 | PASS 的含义 |
|---|---|
| 集合 `car_codes` / `notify_logs` | 集合已存在（不存在会自动创建） |
| 订阅消息模板 | 云函数环境变量 MP_APPID/MP_APPSECRET 已配 + 已发现可用模板（HTTP 直连，不再依赖 cloud.openapi） |
| 运行模式 | 告诉你当前运行模式是 trial 还是 release（来自云端配置 `sys_config/global.runMode`，数据库无合法值时默认 release） |

`allPass: true` 就说明后端全通。任何一项 FAIL，`detail` 里都写明了怎么修，照着改即可。

> `health` 和 `cleanExpired` 这两个 action 不需要用户身份，因此可以在控制台直接跑、
> 也可以被定时触发器调用。其余 action 必须在小程序端通过 `wx.cloud.callFunction` 调用。

**顺便把过期数据清理挂上**（隐私政策里对用户的承诺，不配就是虚假声明）：

触发器已写进 `cloudfunctions/car/config.json` 的 `triggers` 字段，用上面的脚本/手动部署时会自动创建。
若控制台「云函数 → car → 触发器」里没自动出现，手动新增一条：

| 字段 | 值 |
|---|---|
| 触发器名称 | `cleanExpired` |
| 触发周期 | Cron：`0 0 3 * * * *`（每天凌晨 3 点） |
| Payload | 留空即可（云函数已识别 Timer 触发器，自动跑 `cleanExpired`，无需 payload） |

### 第 5 步：配置隐私保护指引（必做，体验版也要）

**不做这一步，「保存到相册」在真机上会静默失败**——不报错，但就是没反应。

`app.json` 里已经打开了 `__usePrivacyCheck__: true`，微信会对相册类接口做拦截。光代码开关不够，**后台必须同步配置**：

1. 登录 mp.weixin.qq.com →「设置」→「服务内容声明」→「用户隐私保护指引」→「更新」
2. 只勾选你**实际用到**的三项（勾选了没用的项 = 超范围收集，同样是驳回理由）：

   | 信息类型 | 用途 | 对应代码 |
   |---|---|---|
   | **手机号** | 车主选填，扫码方一键拨号 | `edit` 页手输，存 `car_codes.phone` |
   | **相册（写入）** | 保存挪车码到手机 | `code.js` / `blanks.js` 的 `wx.saveImageToPhotosAlbum` |
   | **剪切板** | 复制码 ID / openid 便于粘贴 | `util.js` 的 `wx.setClipboardData` |

   勾选后每一项都会弹出「使用场景」输入框，建议**照抄**下面文案（与代码真实行为一致，避免被打回）：

   - **手机号** → 「车主在添加车辆时选填手机号，用于挪车时扫码方一键拨号联系车主，不向第三方共享。」
   - **相册（写入）** → 「用户将生成的挪车码图片保存到本地相册，以便打印张贴。」
   - **剪切板** → 「用户复制挪车码 ID、本人 openid 等内容时，将该内容写入剪切板以便粘贴使用；开发者不会读取剪切板中的任何内容。」

   > ⚠️ 微信模板对剪切板的固定句式是「开发者**读取**你的剪切板，用途是___」，
   > 但本小程序 `util.js` 里只有 `wx.setClipboardData`（**写入**）、没有任何 `getClipboardData`（读取）。
   > 所以用途文案里要写明「写入…不会读取」来消除歧义，审核员一眼能看懂。

3. 整页其余必填项（按下面填基本一次过审）：
   - **是否向第三方共享**：选「否」
   - **个人信息保护负责人 / 联系方式**：填你自己的姓名 + 手机号（管理员本人）
   - **用户行权方式**：填「可在小程序内删除本人车辆信息，或联系客服删除」
   - **存储期限**：选「固定存储期限」→ 填 **90** 天（与云函数 `RETENTION.logDays = 90` 一致，
     由 `cleanExpired` 定时触发器每天凌晨 3 点清理，见第 4 步）
   - **第三方插件 / SDK**：**留空不填**。云开发是微信官方能力，不属于第三方 SDK
   - **补充文档（.txt）**：选填，不传也能过审
   - 勾选项不要多勾（多勾 = 超范围收集，会被驳回）

4. 点「提交」后等待审核通过（通常几分钟到 1 个工作日）

**代码侧已配套做好**：`app.js` 的 `initPrivacy()` 注册了 `onNeedPrivacyAuthorization`，
首次触发隐私接口时会弹窗说明用途，用户同意后放行，点「查看政策」会跳到 `pages/policy/policy`。

> ⚠️ 隐私政策页面里的每一条承诺都必须和代码真实行为一致。
> 尤其 `policy.js` 里的 `logRetentionDays`（默认 90 天）——
> 必须与云函数 `RETENTION` 一致，且定时触发器真的在跑，否则就是虚假声明。

### 第 6 步：启用微信通知（统一一个模板，全自动）

全站只用**一个**通知模板，而且**不用复制模板 ID、不用改代码**——云函数会自动去你账号下找。

**你只需要做一件事：**

1. 登录 mp.weixin.qq.com →「功能」→「**订阅消息**」→「公共模板库」
2. 搜索 `挪车`，选一个标题带「挪车 / 移车」的模板 → 点「选用」
   - 找不到「挪车」就搜 `提醒`，随便选一个 3~4 字段的通用提醒模板，也能用
3. 在「模板详情」里勾选字段（建议：**车牌号 + 内容 + 时间**）
4. 回到小程序，重新进首页 —— 顶部的黄色提示条消失，就说明识别成功了

**它怎么自动匹配的**（知道了好排查）：

- 云函数调用 `subscribeMessage.getTemplateList` 读取你账号下的模板
- 优先挑标题含「挪车 / 移车 / 车辆 / 停车」的；都没有就取第一个
- 再按字段**中文名**自动填内容：

  | 模板字段中文名 | 填入内容 |
  |---|---|
  | 车牌 / 牌照 / 车号 | 脱敏车牌，如 `京A***5` |
  | 时间 / 日期 | 通知时间，如 `2026-09-02 16:41` |
  | 车型 / 车辆 / 品牌 / 颜色 | 车主填的车辆备注 |
  | 内容 / 留言 / 说明 / 备注 | 扫码方留言，默认「有人在找您挪车，请尽快处理」 |
  | 电话 / 手机 / 联系 | 脱敏手机号，如 `138****8888` |

**想手动指定**（账号下有多个模板、自动挑的不对时）：

`cloudfunctions/car/index.js` 顶部的 `MANUAL`：

```js
const MANUAL = {
  templateId: '你的模板ID',
  data: { thing1: '${plate}', thing2: '${message}', time3: '${time}' }
}
```

> 数据源可选：`plate`（脱敏车牌）、`message`（留言）、`time`（时间）、`carModel`（车辆备注）、`phoneMask`（脱敏手机号）。
> 手动模式下字段名必须和模板详情完全一致，否则报 `47003`。
> 改完记得**重新部署云函数**。

**验证是否配置成功**：开发者工具 → 云开发 → 云函数 → `car` → 云端测试，参数填：

```json
{ "action": "templateInfo", "payload": {} }
```

返回 `ready: true` 就 OK；`false` 时 `hint` 字段会告诉你缺什么。

### 第 7 步：真机跑通

1. 开发者工具点「**预览**」，用手机微信扫码
2. 点「开始：输入手机号」→ 填手机号、车牌 → 生成挪车码
3. 首次进入会弹「订阅消息」授权 —— **务必勾选「总是保持以上选择」**再点允许
   - 这是累积通知额度的关键：勾选后每次进小程序会静默累积，不用反复点
   - 没弹授权 / 点了取消 → 首页顶部会有黄色提示条，按提示处理
4. 点「保存到相册」→ 打印

**验证整条链路**：用另一个微信（或让家人）扫你车上的码 → 点「微信通知车主」，
你的微信会收到一条服务通知，首页「可通知次数」同时减 1。

### 第 8 步：提交 ICP 备案（耗时最长，现在就提交）

**未备案的小程序无法提交审核、无法发布上线。** 这一步要 7–20 个工作日，是整个流程里最慢的，建议在调试阶段就先提交。

1. mp.weixin.qq.com 首页 →「**去备案**」
2. 主体类型选「个人」，按提示填：身份证正反面、真实通讯地址、本人手机号 + 应急联系人手机号（**不能与本人号码相同**）
3. 小程序负责人做**人脸核身**（白墙背景、不戴帽子/眼镜/口罩）
4. 提交后等平台初审（1–2 个工作日）
5. 初审通过 → 手机会收到工信部 **12381** 核验短信 → **24 小时内**登录 https://beian.miit.gov.cn 完成短信核验（**超时会被自动驳回，得重提**）
6. 进入通管局审核（1–20 个工作日）→ 下发备案号

> 三个最常见的被驳回原因：接不到审核电话（留一个能打通的号，提交后几天保持畅通）、24 小时内没做短信核验、通讯地址与身份证地址跨省但没交居住证/社保证明。
>
> 备案全程免费，个人主体自己在后台办即可，不需要找代办。

### 第 9 步：发布正式版（让路人扫得开的唯一途径）

备案拿到号之后：

0. **提交审核前先确认两件事已就绪**（否则白等一轮审核、还可能被拒）：
   - 云函数 `car` 已重新部署、小程序代码已上传（「版本管理」里的开发版本含最新改动）
   - 云开发控制台云端测试 `{"action":"health"}` 返回 **5/5**，
     重点看「订阅消息模板」和「空白码管理员」两项是否 ok
1. mp.weixin.qq.com →「管理」→「**版本管理**」→ 对开发版本点「**提交审核**」
2. 填写测试账号：因为你的小程序需要车主先录入车辆，**审核员看不到内容会直接拒**。在「测试账号」栏写明：
   > 本小程序为工具类型，无需登录、无测试账号。打开首页按引导点「添加车辆」，输入任意车牌（如 京A12345）即可生成挪车码，全部功能可直接体验。
   > 补充：首页另有「空白挪车码」功能，需先点首页底部「认领管理员身份」解锁（权限设计如此，非管理员不可见该入口）。解锁后该处变为「⚙️ 管理后台」入口。
3. **服务类目**：个人主体选「**工具 > 信息查询**」或「**工具 > 效率**」。简介里写「车主自主生成联系二维码，供他人扫码发送留言通知，不涉及交易与经营」。
4. 审核通过（通常 1–3 个工作日）→ 回到「版本管理」→ **必须再点一次「发布」**，版本才真正对公众生效
5. **把运行模式切成 `release`（云端配置，无需改代码、无需重部署）**，三选一：
   - **方式 A（小程序内一键切换，最方便）**：打开小程序 → 首页底部「⚙️ 管理后台」→ 顶部「运行模式」开关，点一下切到「正式版」（会弹确认框，切回体验版也一样）。切换后提示哪些码需要重新出图。
   - **方式 B（云端测试调用，推荐·最稳）**：云函数 `car` →「云端测试」→ 参数填：

     ```json
     {"action":"setRunMode","payload":{"runMode":"release"}}
     ```

     查当前模式填 `{"action":"getRunMode","payload":{}}`，会回传 `runMode` / `isRelease` / `envVersion` / `adminConfigured`。
     这两个 action 已加入**免登录白名单**，控制台可直调，不受「名下有车」限制、也不受多实例缓存影响。
   - **不想每次都靠「提审 → 发布」来验证**：见 [免审核测试方案.md](./免审核测试方案.md)。
     其中 `{"action":"dryrun","payload":{"codeId":"xxx"}}` 可以不扫码就预判这张码扫了会发生什么（是否绑定、额度、码图版本与运行模式是否一致）。
   - **方式 C（控制台改数据库）**：云开发控制台 →「数据库」→ 新建集合 `sys_config` → 新增文档 `_id="global"`、字段 `runMode="release"`。
6. 回到小程序，**删除旧车辆重新添加**，让挪车码按正式版重新生成（旧码是体验版的，扫不开）

> ⚠️ 第 4 步的「发布」最容易漏。审核 + 发布都完成，只有「线上版本」一栏出现版本号，路人才扫得开。
>
> ⚠️ 第 5、6 步不做的话，你手里打印出来的还是体验版码，路人扫了照样提示无权限。
>
> 💡 之后想临时切回体验版调试，把 `sys_config/global.runMode` 改回 `trial`（或调 `setRunMode`）即可，全程不用改代码、不用重部署。运行模式切换后云函数已自动刷新缓存，下一次生成挪车码 / 发通知立即生效。

### 第 10 步：打印张贴

| 项目 | 建议 |
|---|---|
| 尺寸 | 6~8 cm 见方 |
| 材质 | 不干胶纸 + 冷裱膜，或直接用塑封机过塑（**防紫外线褪色**） |
| 位置 | 挡风玻璃**左下角内侧**，避开年检标、ETC 位置 |
| 注意 | 别贴在后视镜下方，夏天高温容易脱胶 |

**强烈建议：贴纸上同时印一行手机号。**

备案 + 审核通常要 2~3 周，这期间你的小程序码路人是扫不开的。在码下方加一行「车主电话 138-0000-0000」，即使小程序暂时不可用，路人也能直接联系你 —— 挪车这件事不能等备案。

等正式版上线、确认扫码链路通畅后，再决定要不要换成纯码版本（少印号码=少暴露隐私）。

### 第 11 步：空白挪车码（先印后绑，可选）

如果你想**先印好贴纸、以后再决定绑哪辆车**（或把贴纸转送他人），用空白挪车码。

**配置管理员（必做，否则谁都生成不了）**

空白码生成接口现在只对**管理员本人**开放——普通用户既看不到入口、直接调也会被拒。
管理员身份用 `sys_config/global.adminOpenid` 标识。

> ⚠️ **微信号 ≠ openid**：你平时登录微信用的 `liilillilllililli` 这种字符串是**微信号**，
> 而小程序校验用的是微信系统下发的 **openid**（格式像 `oABC123...` 共 28 位）。
> 两者无法通过任何接口互转，所以**不能**把微信号直接写进 `adminOpenid`，否则连你自己也生成不了。

✅ **推荐：首页一键认领（无需查/粘 openid）**

1. 用你的微信号进小程序首页 → 拉到底部，点「**认领管理员身份**」
2. 弹窗确认后，云函数自动把**你当前的真实 openid** 写入 `sys_config/global.adminOpenid`
3. 首页出现「＋ 空白挪车码」入口和「⚙️ 管理后台」入口；换一个微信登录则两者都看不到，且直接调接口会返回 403
4. 你的 openid 可在**管理后台**顶部查看/复制（首页不再展示真实 openid，避免误触泄露）

**备选方式 B：云端测试直接指定 openid（电脑端操作，无需复制粘贴）**

> 💡 **为什么需要这种方式**：手机剪贴板和电脑剪贴板**互不相通**——
> 你在小程序里点「复制 openid」，粘到电脑浏览器里一定是空的。所以想在电脑上配置，
> 走云端测试直接传参最省事，不用搬运这串 28 位字符。

1. 先拿到你的 openid：云端测试填 `{"action":"getProfile"}` → 返回结果里的 `openid` 字段；
   或进小程序 → **管理后台** → 顶部身份卡直接显示（点一下即可复制）
2. 云开发控制台 → 云函数 `car` →「云端测试」→ 参数填：

   ```json
   {"action":"claimAdmin","payload":{"openid":"o这里换成你的28位openid"}}
   ```

   （把引号里的换成你自己的 openid）
3. 返回 `{"claimed":true}` 即成功

> 该接口会校验 openid 格式（`o` 开头 + 28 位）。**误填微信号会被拒绝**并提示，
> 避免写进去后校验永远不匹配、连本人也生成不了。
> 安全说明：与首页认领同级——**仅在系统尚无管理员时**允许指定，已被认领则需 `force:true` 覆盖。

**备选方式 C：控制台手动填字段**

进 `sys_config` 集合的 `global` 文档，新增字段 `adminOpenid`，值填你的 openid。
（若 `sys_config` 集合不存在，先随便跑一次 `setRunMode` 或 `claimAdmin` 让系统自动创建。）

> 验证：跑 `{"action":"health"}` 自检，「空白码管理员」项应显示「已配置（oxxx…）」，整体 5/5。

### 第 12 步：管理后台（管理员专属，全量挪车码的增删改）

首页只管**自己的车**；所有码的统一管理在 **⚙️ 管理后台**（首页底部入口，仅管理员可见）。

> 前端隐藏入口只是体验层，真正的边界在服务端：每个 `admin*` action 都在云函数里
> 独立校验一次管理员身份，非管理员直接 403。

**能做什么**

| 区块 | 内容 |
|---|---|
| 总览 | 码总数 / 已绑定 / 空白码 / 已停用 + 今日新增、近 7 天、通知成功数 |
| 搜索筛选 | 关键词搜「码 ID / 车牌 / 备注 / 车主 openid」；筛选「全部 / 已绑定 / 空白码 / 已停用」 |
| 单码管理 | 查看码图、**重新出图**（可强制正式版/体验版）、启用·暂停、**解绑还原**、删除 |
| 诊断 | 每张码展开后显示一句人话结论（能不能扫开、额度、版本是否匹配） |
| 运行模式 | 体验版 ↔ 正式版全局开关（原首页开关已移到这里） |
| 空白码 | 批量生成（1~5 张），选正式版/体验版 |

**两个容易混淆的操作**

| 操作 | 效果 | 什么时候用 |
|---|---|---|
| **解绑还原** | 清空车牌与联系方式，还原成空白码；**码 ID 和已打印的贴纸不变**，别人扫码可重新绑定 | 车主换车、贴纸回收、误绑 |
| **删除** | 记录 + 云存储码图一起清掉，**立即失效且不可恢复** | 测试残留、用户注销、误生成 |

**后台新增的云函数 action**

| action | 作用 |
|---|---|
| `adminStats` | 总览统计 |
| `adminList` | 全量列表（keyword / filter / 分页），回传 `expectEnv` 供前端标红版本不符的码 |
| `adminDetail` | 单码详情：完整手机号、车主 openid、健康诊断 `verdict` |
| `adminUpdate` | 改车牌 / 手机号 / 备注 / 启停 |
| `adminUnbind` | 解绑还原为空白码 |
| `adminRebuild` | 强制重新出图（可指定 `envVersion`） |
| `adminRemove` | 删除任意码 + 清理云存储码图 |

> ⚠️ **列表默认脱敏**：手机号显示为 `138****8888`，车主 openid 显示为 `oXKsUxhE…IOy8`。
> 完整号码只在展开某一张后、再点「显示」才出现 —— 避免后台一屏全是真实号码。
>
> ⚠️ **列表里标红「版本不符」的码一定要重新出图**：码的版本是烧死在图片里的，
> 切了运行模式旧图不会自动变，这类码正是「扫码打不开」的重灾区。

### 审核期间能不能先把贴纸印出来？

**可以**，但必须选「正式版」——因为小程序码的**版本是烧死在图片里的，事后改不了**：

| 出码版本 | 现在能打印吗 | 现在能扫吗 | 正式发布后 |
|---|---|---|---|
| **正式版（release）** | ✅ 可以印 | ❌ 扫不开（小程序还没发布，属正常） | ✅ 扫码直接绑定 |
| **体验版（trial）** | ❌ 印了也白费 | ✅ 能扫（可自测绑定流程） | ❌ 作废，需重印 |

所以：想**提前印贴纸**就选「正式版（打印）」；想在发布前**验证绑定流程**就选「体验版（自测）」。

> 技术上可行的原因：调用 `wxacode.getUnlimited` 时 `checkPath` 恒为 `false`，
> 微信不会校验页面是否存在于「已发布的正式版」，因此未发布的小程序也能生成正式版码。

安全兜底：一旦某张码以正式版出过图，之后即使运行模式还是体验版，
`getWxacode` 也**不会**把它降级重生成——否则你已贴出去的贴纸会被悄悄作废。

**怎么用**

1. 首页点「＋ 空白挪车码」
   - 当前是体验版运行模式时，先弹窗让你选用途：**正式版（打印）** / **体验版（自测）**
   - 已是正式版运行模式则直接选张数
   - 选完用途再选张数（1~5 张）→ 立即生成
2. 跳到批量展示页，每张码一张卡片，点击可放大、长按转发；
   页顶会写明这批是「正式版码（可打印）」还是「体验版码（会作废）」
3. 点「全部保存到相册」可一键存到手机 → 去打印或转发
4. 扫码任何一张码 → 页面提示「这是一张空白挪车码」→ 点「绑定我的车辆」
5. 填写车牌号 + 手机号 → 绑定完成，这张码归他

**规则与边界**

| 项 | 行为 |
|---|---|
| 绑定权限 | **先到先得**：任何人扫到都能绑定，无需凭证 |
| 所有权 | 绑定后记录的所有权（openid）转移给绑定者，生成者的列表里不再显示它 |
| 生成者自己绑 | 同样走「先到先得」，绑定前后都是你，没有区别 |
| 并发抢绑 | 云函数用条件更新 `where({codeId, bound:false})` 保证原子性，后到者会收到「刚被别人绑定了」（409） |
| 绑定前扫码 | 只显示绑定引导，不写「被扫码」日志、不触发频控，也不会污染绑定后的通知记录 |
| 未绑定的码 | 首页显示为橙色虚线卡片「待绑定」，可以提前删除（删了码图立即失效） |
| 单次上限 | 「＋ 空白挪车码」面板最多选 5 张。服务端 MAX_BLANK_BATCH 同步做了硬上限（防止绕过前端） |
| 批量出码失败 | 任一张失败不影响其他张，返回里 failed 字段给张数。前端只展示成功的码 |
| 出码版本 | 生成时烧进图片、不可改。用 `envVersion` 参数指定 `'release'` / `'trial'`，不给则跟随运行模式；云端测试可直接传 `{"action":"createBlanks","payload":{"count":2,"envVersion":"release"}}` |
| 降级保护 | 已出正式版图的码，不会因为运行模式切回体验版而被重生成覆盖（避免已贴出的贴纸失效） |

**数据模型**：空白码就是 `car_codes` 里 `bound: false`、`plate` 为空的记录。
老数据没有 `bound` 字段，一律按「已绑定」处理，不受影响。

> ⚠️ 因为是先到先得，空白码贴纸在绑定前不要随意展示给无关的人，
> 否则可能被别人抢先绑定。绑定完成后才和普通挪车码完全一样。

## 四、常见问题排查

### 订阅消息发不出去

| 错误码 / 现象 | 原因 | 解决 |
|---|---|---|
| 首页提示「未找到可用的通知模板」 | 公众平台还没选用模板 | 按第 6 步去公共模板库选用一个 |
| `templateInfo` 报「未配置 MP_APPID / MP_APPSECRET」 | 云函数缺环境变量 | 到云函数 `car` →「配置」→「环境变量」填 `MP_APPID` 与 `MP_APPSECRET`，保存后重新部署 |
| `47003` 参数错误 | 手动模式下字段名写错，或字段值超长 | 自动模式不会出现；用了 `MANUAL.data` 就核对字段名。`thing` 最长 20 字符（代码已自动截断） |
| `43101` 用户拒收 | 额度已用完，或车主取消了授权 | 车主重新进小程序，等授权弹窗出现并允许；页面会显示剩余次数 |
| `40037` / `40036` | 模板 ID 无效 | 到公众平台「我的模板」重新选用（自动模式下代码会清缓存重拉） |
| `48001` | 未开通订阅消息能力 | 公众平台「功能」→「订阅消息」确认已开通 |
| 真机能发，开发者工具报错 | 工具不支持订阅消息授权 | **正常现象**，必须用真机预览测试 |
| 通知一直收不到 | 运行模式与扫码方版本不匹配 | 已由云函数按「运行模式」自动设置：`trial` → `trial`、`release` → `formal`，无需手动改 `TEMPLATE`；若不一致，检查云端配置 `sys_config/global.runMode` 是否为预期值 |
| 自动挑的模板不对 | 账号下有多个模板 | 到第 6 步的 `MANUAL` 里手动指定模板 ID |

### 其它

| 现象 | 排查 |
|---|---|
| 一切都不确定从哪查起 | 先跑第 4 步的 `health` 自检，它会逐项告诉你哪一项没通过 |
| 扫码提示「挪车码无效」 | 云函数没部署成功，或数据库集合没建；看云开发「日志」里的报错 |

## 五、个人主体合规红线自查

个人主体做挪车类小程序，以下 5 条是硬红线，踩中任意一条都会被驳回（甚至封禁能力）。
本项目已按这些约束设计，改动代码时请对照检查。

| # | 红线 | 本项目状态 | 代码位置 |
|---|---|---|---|
| 1 | **禁止虚拟号 / 中转呼叫 / 短信通知** | ✅ 不涉及。<br>只用两种能力：微信订阅消息 + `wx.makePhoneCall`（系统拨号，不经服务器） | `cloudfunctions/car/index.js` 的 `notify`<br>`pages/notify/notify.js:224` |
| 2 | **手机号不得强制必填**（最小必要） | ✅ 选填。<br>不填也能生成挪车码，仅走微信通知 | `pages/edit/edit.js` 的 `onSave` |
| 3 | **必须配置隐私政策**，写明收集项、用途、存储周期 | ✅ 已内置页面 + 后台指引<br>（后台指引需你手动配置，见第 5 步） | `pages/policy/*`<br>`app.js` 的 `initPrivacy()` |
| 4 | **禁用交警 / 交管 / 官方挪车等政务词** | ✅ 全项目零命中。<br>文案统一用「挪车助手」「联系车主」 | 全局（可用 `grep -rn "交警\|交管\|12123" .` 复查） |
| 5 | **不得售卖挪车码实物、不得付费会员** | ✅ 无任何支付、商城、会员代码 | 全局（`grep -rn "requestPayment\|会员" .` 应为空） |

### 逐条说明

**1. 关于拨号能力**

`wx.makePhoneCall` 是微信**基础 API**，个人主体可用，不需要类目、不需要认证。
它做的是「调起手机系统拨号盘并填入号码」，通话完全走运营商网络——
**不经过我们的服务器，不产生中转，也不获取通话内容**。这与「虚拟号 / AXB 中转呼叫」是两回事。

真正需要企业资质的是：号码隐私保护（AXB 中间号）、短信代发、云通信呼叫。
这些本项目一律没有，隐私政策第四章也已向用户明确声明「不提供此类服务」。

> 若日后要接隐私号，必须换成**企业/个体工商户主体**，并申请「工具 → 停车服务」类目。

**2. 关于明文展示手机号**

`config.js` 的 `SHOW_PLAIN_PHONE` 默认 `true`（体验版自用，方便直接拨）。
这是**用户主动填写并同意公开**的，隐私政策第四章已写明"该号码会公开展示给扫码的人，可随时删除"。
但要注意：**公开发布上线时必须改成 `false`**，否则号码会被任意路人拍摄采集，
审核大概率以「用户信息安全」为由驳回。

**3. 关于存储周期**

声明了 90 天就必须真的删。`RETENTION`（云函数）与 `policy.js`（页面）必须一致，
且定时触发器必须配置。三者缺一，就是虚假声明。

**4. 关于文案自查**

改文案后跑一次：

```bash
grep -rn "交警\|交管\|车管所\|12123\|官方挪车\|政务\|公安" --include="*.js" --include="*.wxml" --include="*.json" --include="*.md" .
```

应无输出。另外小程序名称、简介里也别出现这类词，注册时就会卡。
名称建议：`XX挪车助手`、`挪车码`（避开「一键挪车」「挪车服务」这类像政务服务的表述）。

## 六、个人主体发布上线：可行性与风险

个人主体**可以**发布上线（第 9 步已给出路径），但有两个真实风险，提前有心理准备：

**风险 1：类目没有完全对口。** 微信没有「挪车」这个个人开放类目，「停车服务」类目也不对个人开放。实操上选「**工具 > 信息查询**」或「**工具 > 效率**」提交，是目前个人主体过审概率最高的做法。但如果审核员认定你的小程序实质是"挪车服务"而非工具，会以「类目与实际内容不符」驳回。

**风险 2：明文手机号可能被判违规。** 公开上线后，扫码页明文展示手机号会被任意路人看到、拍摄。审核可能以「用户信息安全」为由要求整改。

### 降低风险的做法

- 简介写成工具属性：「车主自主生成联系二维码，供他人扫码发送留言通知，不涉及交易与经营」
- 名称避开「一键挪车」「挪车服务」「官方挪车」这类像政务/商业服务的表述，用「XX挪车助手」「挪车码工具」更稳
- 若因明文号码被驳，把 `config.js` 的 `SHOW_PLAIN_PHONE` 改成 `false`（脱敏展示 + 点拨打时系统弹窗显示），改完重新提交

### 若个人主体始终过不了

那就需要企业/个体工商户主体：

1. **个体工商户或公司营业执照**（个体户办理通常几百元，多数地区可线上办）
2. **微信认证**：300 元/年
3. **类目**：`工具 → 停车服务`（以平台当时开放范围为准）
4. 备案、隐私保护指引、订阅消息模板需按新主体重新走一遍

> 个人主体无法变更为企业主体，只能重新注册一个小程序。所以如果只是自用或小范围使用，可以先按个人主体试；确定要商业化再另起企业主体。

### 上线后的隐私合规要点

- 建议把 `config.js` 里的 `SHOW_PLAIN_PHONE` 改成 **`false`**
  （调试阶段默认 `true` 明文显示，方便验证；公开上线后号码会被任意路人看到、拍摄、采集）
- 关掉后手机号按 `156******77` 脱敏展示，点「拨打」时由微信系统弹窗显示完整号码
- **过期数据清理**：云函数已内置 `cleanExpired`，需在云开发控制台加定时触发器才真正生效：
